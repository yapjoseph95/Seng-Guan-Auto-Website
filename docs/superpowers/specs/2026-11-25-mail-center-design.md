# 后台邮件中心与新邮件通知

## 已确定的需求

以 Resend 接收和发送 sales@sengguanauto.com.my 与 admin@sengguanauto.com.my 的邮件，在现有网站后台统一查看和回复。用户不购买企业邮箱托管。新邮件可通知 sengguanauto.app@hotmail.com 和 sengguanauto.bos@hotmail.com，通知链接打开后台对应邮件。

## 方案

已选择 Resend 收发加自建后台邮件中心。保留 Cloudflare 转发加另设发信页面会使收发分离；企业邮箱加 Outlook 需要付费，均不符合用户选择。后台沿用现有管理员认证、Cloudflare Pages、D1 和 R2，不另建账号系统。

## 界面与行为

- 后台增加邮件入口，提供收件箱、已发送、写信、查看邮件与回复。两个公司邮箱可切换；沿用现有后台语言与样式。
- 邮件详情显示发件人、收件人、主题、时间、内容与附件。回复默认使用收到邮件的公司地址，并保留邮件线程标识。API 不接受其他发件身份。
- 设置中提供新邮件通知开关及通知收件人。默认开启，并通知上述两个 Hotmail，无论新邮件寄给 sales 还是 admin。这与先前各地址单独转发的行为不同，是本次通知请求的默认解释。
- 通知包含原始发件人、公司收件地址、主题、收信时间与“查看邮件”链接，不嵌入完整正文或附件。
- 链接示例：/admin?section=mail&message=<opaque-id>。已登录则直接定位；未登录先完成现有 OTP 登录，再显示该邮件。链接不携带会话凭据，不绕过授权。
- 第一版沿用当前管理员白名单，获授权的后台管理员均可访问两个邮箱与通知设置，不把 Hotmail 通知地址自动加入管理员白名单。

## 接收、保存与通知可靠性

- 增加 Resend email.received webhook。先验证原始请求签名和时间，再通过服务端 API 获取邮件正文与附件；不信任请求中的任意下载地址。
- D1 保存邮件索引、已读状态、发送状态、通知设置与投递任务；正文与附件使用独立的 R2 邮件前缀，不公开暴露。
- 邮件内容属于外部不可信数据。HTML 在隔离环境显示，禁用脚本、表单、顶层跳转及默认远程资源加载；附件下载需管理员授权。
- 使用 Resend 邮件 ID 去重接收事件；通知按邮件和目标地址建立独立任务，记录发送结果并使用固定幂等键重试。通知失败不丢弃原邮件，也不把失败标记成已发送。
- 邮件中心保留原邮件，不依赖 Resend 日志保留期限；删除或保留策略另行确定，第一版不自动清理邮件。
- 发信使用服务端密钥、管理员授权与同源检查；防重复发送。通知邮件不对本站邮箱发送，避免形成通知循环。

## 接入与上线顺序

1. 先实现数据库、API、后台页面和测试。
2. 在 Cloudflare Production 配置 RESEND_API_KEY 和 RESEND_WEBHOOK_SECRET。密钥不放入代码或前端。
3. 在 Resend 核实根域名的发信权限、收信功能、实际 MX 值和额度，配置 webhook，先用 Resend 测试地址验证流程。
4. 数据库迁移和应用部署完成后，再停用根域名旧 Cloudflare Email Routing 并切换到 Resend 提供的 MX；保留 Resend 发信验证和网站 DNS。
5. 经用户授权发送实际测试邮件，验证两个公司邮箱的收信、回复、附件、重复事件、通知、登录后定位以及通知失败重试。

## 当前限制与验证要求

Cloudflare MCP 仍返回缺少 zone.read 权限；当前会话也没有 Resend 连接工具。公开 DNS 只能确认现有 Cloudflare 根域名收信 MX 与 Resend 发信相关记录，不能确认转发规则或 Resend 后台实际状态。不能在接入验证前宣称线上可用。

通知及人工发信均消耗 Resend 发送额度；给两个地址通知通常需要两份收件投递额度，最终以账户计费规则为准。接入前核对当前免费方案及接收限制，不承诺所有用量永久免费。

测试覆盖：未授权访问被拒绝、无效/过期 webhook 签名、事件去重、通知目标校验、发送幂等、HTML 隔离、附件权限以及登录前后深链接保持。上线时切换 MX 前须确认旧规则下的其他收件地址，避免遗漏业务收信。
